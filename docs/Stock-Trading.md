# 交易终端（模拟交易）

交易终端是自由交易商店里的第七个页签，用一套完全虚拟的指数行情，让玩家用服务器货币做**保证金式做多/做空**。它不产出物品、不影响商店价格，也不接入任何现实市场数据；行情、撮合、强平与账本全部由服务端权威计算。

> 服务端需要安装 FTB Money（或提供同名反射接口的经济模组）。经济系统不可用时，终端仍可查看行情，但所有下单会被拒绝。

---

## 1. 入口

| 位置 | 行为 |
|------|------|
| 商店页右侧页签「交易终端」 | 打开终端，默认选中「综合经济指数」 |
| `/market stock` | 直接打开商店并切到交易终端 |
| `/market` | 打开普通商店页 |

页签强调色是金色（`PageTheme.TAB_ACCENTS` 第 7 色 `0xFFFFD166`）。

---

## 2. 品种

内置 5 个虚拟指数，价格单位是「分」，界面显示两位小数：

| id | 名称 | 基准价 | 15 秒波动 | 说明 |
|----|------|--------|-----------|------|
| `composite` | 综合经济指数 | 100.00 | — | 由其余 4 个品种按权重合成 |
| `circuit` | 电路板指数 | 128.00 | 0.22% | 权重 0.30 |
| `energy` | 能源指数 | 86.40 | 0.18% | 权重 0.25 |
| `ore` | 矿石指数 | 94.20 | 0.20% | 权重 0.25 |
| `agri` | 农业指数 | 61.50 | 0.26% | 权重 0.20 |

综合指数不独立随机：

```text
composite = Σ weight_i × (price_i / base_i) × 10000
```

因此它能当“大盘”看，和四个成分品种不会出现走势互相打架。每个品种都有独立的均值回归锚点、共同因子与低频跳变；锚点限制在基准价的 0.55–1.90 倍，价格限制在 0.30–3.00 倍。

---

## 3. 行情与图表

- 服务端每秒推进一次价格，每 **15 秒**收一根 OHLCV K 线。
- 服务端保留最近 **240 根**，客户端每次整包同步 **100 根**；之后只发价格，K 线在收盘时补发。
- 图表包含蜡烛、影线、MA5 / MA10 / MA20、成交量、价格网格、右侧价格刻度、时间刻度、最后收盘参考线与十字光标。
- 滚轮缩放 **20–100 根**；按住图表左右拖动平移。默认显示 60 根。
- 配色遵循 A 股习惯：**红涨绿跌**；多头/盈利为红，空头/亏损为绿。
- 窗口较小（约 **520 × 300** 以下）时自动切换为精简模式：保留账户摘要、品种切换和 K 线图表，隐藏下单区与底部页签；放大窗口后恢复完整界面。只有小于 **200 × 110** 时才只显示品种与最新价。

服务器关闭期间行情**不推进**；重启后从存档继续，并把整条时间轴平移到当前时刻，不会补算停机期间的涨跌。

## 4. 账户

| 字段 | 含义 |
|------|------|
| 余额 | 钱包里可自由使用的钱（FTB Money） |
| 权益 | 余额 + 冻结保证金 + 待入账 + 全部持仓浮盈 |
| 可用 | 等于余额；开仓时保证金与手续费已从余额扣除 |
| 冻结 | 当前所有持仓占用的保证金 |
| 已用保证金 | 与冻结相同，单独列出便于核对 |
| 实际杠杆 | Σ(开仓价 × 数量) / 权益 |
| 维持保证金率 | 50% |

内部所有金额用 `long` 的“分”，手续费向上取整、盈亏向下取整，避免靠四舍五入套利。

---

## 5. 下单

- 只有**市价单**：买入开多、卖出开空。
- 数量 1 – 1,000,000 张/品种；快捷 `+1` / `+10` / `+100` / `最大`。
- 杠杆档位：**5× / 10× / 20× / 50× / 100×**，默认 20×。
- 成交价含滑点：买入向上 0.02%，卖出向下 0.02%。
- 手续费：名义价值的 **0.055%**，开仓、平仓各收一次。
- 保证金：`ceil(名义价值 / 杠杆)`。

开仓时从钱包扣除 `保证金 + 手续费`，保证金进入冻结；平仓时按平仓比例释放保证金，并结算：

```text
浮盈     = 方向 × (标记价 - 开仓价) × 数量
平仓净额 = 释放保证金 + 浮盈 - 平仓手续费
```

同一品种允许同时持有多单和空单（锁仓）；限仓按**单方向**累计，各自不超过 1,000,000 张。单账户最多同时持有 **64 笔**持仓，达到上限后需先平仓。

---

## 6. 强平

每个持仓每秒检查一次：

```text
保证金 + 浮盈 ≤ 保证金 × 50%
```

触发后按市价整笔强制平仓，成交价同样含反向滑点。若结算后钱包为负，按 0 处理（差额记为坏账）。在线玩家会收到 `[交易终端]` 聊天提示；离线玩家会在下次登录时收到通知。

---

## 7. 仓位保护

选中持仓后可设置止损/止盈，两种模式：

| 模式 | 输入 | 触发条件 |
|------|------|----------|
| 价格 | 止损价、止盈价 | 多单：标记价 ≤ 止损 或 ≥ 止盈；空单相反 |
| 盈亏金额 | 最大亏损、目标盈利 | 浮盈 ≤ -止损金额 或 ≥ 止盈金额 |

- 价格模式会校验方向：多单必须 `止损 < 标记价 < 止盈`，空单相反。
- 盈亏模式的止损金额上限是该持仓的保证金；止盈金额不限。由于亏损达到保证金的 50% 时会先触发强平，止损金额建议不超过保证金的 50%。
- 服务端每秒检查，触发后**整笔**市价平仓，记录类型为「止损」或「止盈」。
- 「清除保护」只清除当前持仓的保护单，不影响持仓。

---

## 8. 记录与离线结算

- 每次开仓、平仓、强平、止损、止盈都会写一条成交记录；每个账户保留最近 **50 条**。
- 记录是账本，不参与余额计算。
- 服务器运行期间，离线玩家的持仓照常计价、触发保护和强平。
- 离线强平无法直接写 FTB Money，结算金额先记入账户的 `pendingCash`；玩家登录时一次性写回钱包，并在聊天里补发通知。
- 停机期间行情不推进，因此不会在重启时补算离线盈亏。

---

## 9. 存档

`StockDatabase` 是主世界的 `WorldSavedData`，数据名 `quantumhue_stock`，保存：

- 行情引擎状态（价格、锚点、当前 K 线、最近 240 根 K 线、时间轴）；
- 每个玩家的账户（冻结、待入账、持仓、保护单、最近 50 条记录、离线通知）；
- 快照序号。

每根 K 线收盘、每次成交、每次保护单变更都会 `markDirty()`，由原版按周期落盘。

## 10. 网络

| 方向 | 包 | 内容 |
|------|----|------|
| C→S | `MessageStockAction` | `REQUEST` / `POLL` / `OPEN` / `CLOSE` / `SET_PROTECTION` / `CLEAR_PROTECTION` |
| S→C | `MessageStockView` | 账户数字、品种价格与涨跌幅、按需附带的 K 线、持仓、记录、通知/错误 |

- 打开页签时发 `REQUEST`，拿整包（含 100 根 K 线）；关闭即停止轮询。
- 之后每秒 `POLL`，只带价格与账户数字；K 线在收盘时补发，记录只在开仓/平仓响应里带。
- 客户端 `StockClientStore` 负责合并：带 K 线就整体替换，不带就保留旧 K 线并用最新价修补最后一根。
